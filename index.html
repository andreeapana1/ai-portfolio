Project 1

Examiner Mode: an oral exam simulator

Built with Claude, Python, JavaScript and GitHub Pages · Course: AI in Accounting and Business, SDU

Problem
The course's practice website for the Data Analytics in Accounting exam only listed questions. Students could read them but never practise the real situation: answering out loud, under time pressure, while an examiner asks follow-up questions. At my own oral exam I didn't know what to expect, and I panicked.
What I built
An examiner mode that recreates the exam. The site reads each question aloud, the student answers out loud against a countdown, and the examiner interrupts with a follow-up chosen from what the student has said so far. It can quote a wrong number back, ask for a missing unit, or catch a classic mistake such as "significant means important". Students pick a friendly, standard or strict examiner.
Feedback
At the end the student sees what they said written down, a checklist of the key points they covered or missed, why each follow-up was asked, the model answer, and notes on how they sounded (pace, filler words).
Result
The teacher gave very positive feedback and said he had never seen an idea like this from a student before.

Project 2

Company Policy Assistant: an AI chatbot in Slack

Built with Python, Gemini models, a vector index, Slack and Cloudflare Workers · Course: AI in Accounting and Business, SDU

Problem
Employees struggle to find answers in a large policy library (98 policies here), and a confident wrong answer can be costly.
What I built
A Slack bot that answers questions such as "How many vacation days do I get?". It finds the relevant policy, answers in a thread and quotes the policy text it used, so every answer can be checked. A public website lets anyone ask their own question, with the API key kept in a Cloudflare Worker instead of the code.
How I chose
I tested three approaches on the same 22 questions and measured accuracy, unsupported answers, speed and cost.
MetricRules-based searchAI with all policiesAI with vector index (chosen)
Correct policy found68%100%95%
Unsupported answers27%5%5%
Declined when no policy exists50%100%100%
Average response time< 0.01 s1.12 s1.34 s
Tokens per question02,974330
Decision
The vector index approach is almost as accurate as sending every policy to the AI, uses about nine times fewer tokens, and keeps working as the policy library grows. That is the version the Slack bot runs.
Controls
The bot declines instead of guessing when no policy covers a question, and cites its source with every answer.

Project 3

Transfer Referral Assistant: AI support for KYC/AML checks

Built with Claude · Based on my work as a money transfer agent · Fictional cases only

Problem
At a money transfer counter, the clearest warning signs come from the conversation with the customer, not from the numbers. Tellers must notice them, stay calm and professional, and write a clear referral to the compliance team.
What I built
A demo that reads a teller's notes and checks them against four warning signs from my own work: the sender doesn't know the receiver, becomes uneasy when asked about the relationship, won't explain the transfer, or can't show where the money comes from. It quotes the exact words behind each sign and drafts the referral.
Test
On 8 fictional cases, a keyword check found 7 of 10 warning signs and raised 2 false ones. It missed signs written in different words, and it flagged "without hesitation" as hesitation. The AI review found all 10 with no false signs and the right referral decision in every case.
Controls
The tool never decides. It only prepares the referral; the teller checks the quotes and the compliance team decides on an additional interview.

Project 4

P-card Audit Tool: AI-assisted internal audit of purchasing cards

Built with Python, Streamlit, SQLite and the Gemini API · Case: Oklahoma State University purchasing cards, 2010–2014 (anonymised data)

Problem
Employees with purchasing cards must follow a spending policy, and internal audit has to check that they do. With almost 490,000 transactions over five years, checking by hand is impossible, and auditors without SQL skills can't query the database themselves.
What I built
A web app with two tabs. In Ask a Question, an auditor types a question in plain English; AI writes a database query, runs it and answers from the actual results, showing the query so it can be checked. The Prohibited Purchases Dashboard searches transactions by year and keyword across 14 categories the card policy prohibits, such as alcohol, cash advances and gift cards.
Example
A vendor search for "liquor" returns 10 transactions worth $9,179. Nine of them, worth $9,148, were made by the same cardholder and labelled "general purchase". That is the kind of pattern an auditor would follow up with supporting documents.
Controls
Two safety layers make sure the AI can never change the data: only a single read-only query is allowed through, and the database is opened in read-only mode. Matches are shown as potential exceptions, not proof, and the API key is kept out of the code.

Master's thesis: AI and the performance evaluation of accountants

Co-authored with Daniela Gelvere · University of Southern Denmark · due June 2027

Question
When AI takes over routine accounting work, how should firms measure and evaluate what their accountants actually contribute?
Approach
A case study built on interviews with accounting and payroll firms, analysed through management accounting and agency theory.
Use of AI
AI is part of the research workflow: transcribing and analysing interviews, coding qualitative data, and writing code for data analysis where needed. AI output is checked against the original sources.
Why it matters
It connects my two interests: using AI in my own work, and understanding how AI changes performance measurement and control in organisations.

How I work with AI

In finance, AI is only useful if you can trust the answer. That's why every project I build follows the same four steps.

  1. 1

    Start from a real problem

    I build for a situation I have been in myself, not for the technology.

    In practice

    I panicked at my own oral exam because I didn't know what to expect. That became Examiner Mode.

    See Project 1 →
  2. 2

    Compare before choosing

    I try more than one approach on the same test and let the numbers decide.

    In practice

    Three approaches, 22 questions: the vector index found the right policy 95% of the time with nine times fewer tokens.

    See Project 2 →
  3. 3

    Keep people in charge

    The AI prepares the work. A person checks it and makes the decision.

    In practice

    The Referral Assistant drafts the referral, but the teller checks the quotes and compliance decides.

    See Project 3 →
  4. 4

    Build in controls

    Every answer shows its source, and the AI can never change the underlying data.

    In practice

    The P-card tool only runs read-only queries and opens the database in read-only mode.

    See Project 4 →

And when the AI doesn't know, it should say so. My Policy Assistant declined every question that no policy covered, instead of inventing an answer. In compliance work, "I don't know" is better than a confident guess.
